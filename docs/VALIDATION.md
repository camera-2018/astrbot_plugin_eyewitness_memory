## v0.1.3 局部原文与只追加注入（2026-09-20）

- 每条来源前后各 10 条，同群去重、时间排序；保留已采集的引用父消息。每条记忆片段最多 50 条/18,000 字符，直接来源优先；核验和管理页共用这份片段。
- 新消息读取原始 OneBot time（SDK 适配器的 timestamp 是接收时间，未当成发送时间使用）；旧记录明确标为采集时间。SQLite schema 1→2 保留数据，升级可重入，旧代码拒绝打开新版库。
- 主模型获得带时间、昵称、ID 的原文；默认总注入 8,000 字符，重叠记忆复用已经展示的消息。原文不足以放入预算时放弃该条注入，不退化为无来源摘要。
- 去掉临时标记，保留已追加的历史快照；全历史版本标记去重，新版本可追加。不改 system prompt、原 prompt、既有历史和此前附加内容。不承诺上游缓存命中率，不干预核心压缩/reset。
- 65 项后端测试、3 项 Chromium E2E、TypeScript/Vite 和 Ruff 通过。覆盖同秒排序、跨群隔离、来源保留、超预算、旧库迁移、隐私删除竞态、新版本及重叠去重。
- 在生产 AstrBot SDK 下以隔离目录运行检查，验证原始平台时间、实际 assemble_context 顺序、历史序列化保留、两轮历史前缀不变、停用、关闭与重载。没有向群发送合成测试消息。
- 仅热重载测试实例插件；五群白名单、辅助模型和 200 次预算未改，仅将该安装的注入字数预算从 1,600 调到 8,000。22 条旧记忆完整保留；已观察到新消息 sent_at 正常写入。
- 管理页实测一条记忆展开 42 条原文，直接来源与 +08:00 时间正确，页面没有 JS 错误。旧源码与 SQLite 已备份，容器启动时间不变；真实原文、截图与备份不进入仓库。
- 上述为功能与数据迁移验证；本轮没有另行调用真实 Gemini 测试召回质量，也不以合成测试代替真实语料质量评估。
