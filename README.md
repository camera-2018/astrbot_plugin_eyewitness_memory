# Eyewitness Memory · 群聊记忆

让 AstrBot 记住群友聊过的事，想起来时还能翻回原文核对。

例如，群友曾经说过“我报名了十一月的摄影比赛”。过了一段时间，他再问“我之前说的比赛是什么时候？”，插件会查找相关记忆，翻出当时前后的聊天，确认内容后交给机器人参考。

整个过程自动进行，群友不需要使用记忆命令，机器人也不需要主动调用工具。找不到可靠的记录时，就不补充记忆，正常聊天继续。

## 有什么特点

- **记忆有出处**：不只保存一句总结，还保留对应原文。查看时能看到前后聊天、发言人和每句话的时间。
- **各群分开**：一个群的记忆不会自动用到另一个群里。
- **回复前核对**：先判断记忆是否相关，再用原文检查，尽量避免把玩笑、转述或别人的事记到某个人身上。
- **网页管理**：在 AstrBot 里查看、搜索、修改、停用或删除记忆，也能测试某句话会召回什么。
- **重开会话也保留**：记忆独立存储，不会因为聊天 reset 就清空。

目前支持 **QQ 群聊（aiocqhttp）**，不支持私聊记忆。插件不会改变机器人原有的唤醒方式；只有 AstrBot 准备回复时，才会自动查找相关记忆。

## 安装

需要 AstrBot **4.28.1 或以上的 4.x 版本**，Python **3.11+**。

在 AstrBot 插件管理中，使用以下仓库地址安装：

```text
https://github.com/camera-2018/astrbot_plugin_eyewitness_memory
```

安装后，从 AstrBot 的「插件页面」打开「群聊记忆」。管理页面使用 AstrBot 的登录权限，不需要另开端口或单独登录。

如果装过旧名称的版本，请先备份并迁移原有数据和配置，不要同时安装两份。

## 配置与启用

新安装默认关闭，也不会记录任何群。可以在 AstrBot 的「插件配置」或本插件管理页面的「设置」中配置，**两处读写同一份设置**。原生配置页的辅助模型使用 AstrBot 内置选择器，插件页面也会列出已配置的模型，不需要手填 ID。

1. **选择辅助模型**：选择已配置的聊天模型。它负责提取记忆和核对原文，可以与机器人平时聊天的模型不同；需要能按要求返回 JSON。
2. **填写允许记录的群**：一行一个完整会话标识，例如 `default:GroupMessage:123456`。这里不是只填群号；`default` 也要与 AstrBot 中实际的平台标识一致。
3. **排除其他机器人**：填写群内其他机器人的账号，避免把它们的回复当成群友的经历。
4. **启用插件**：将「插件开关」切到启用并保存。可以先开一个群，观察记忆是否准确。

### 要不要配置 Embedding 和 Qdrant？

**不是必需的。** 只配置辅助模型就能使用，默认按关键词查找记忆。

如果希望“换个说法也能找到相关记录”，可以额外配置：

- **Embedding 模型**：在 AstrBot 中添加后，在本插件选择对应的 Provider ID。
- **Qdrant**：填写服务地址和可选的 API Key。插件页面不会显示已有密钥，留空保留原值；需要删除时使用「清空密钥」后保存。

两项都配置后才会启用语义检索。「独立 Collection 前缀」可以保留默认值，不要和其他插件共用索引。

在另一处改过配置后，可以点击「重新读取配置」更新当前页面。原生配置保存时 AstrBot 会重载本插件，已有记忆不受影响。

## 怎么查看和管理

打开「记忆库」，点击一条记忆，就能看到它的内容、来源和附近的聊天。发现记错了，可以修改内容、停用或删除。

记忆有三种状态：

- **生效中**：可以被检索，但是否用于回复仍要经过相关性判断和原文核验。
- **待审核**：暂时不会用于回复。比如信息来自他人转述，或来源中的发言人与记忆主体不一致，需要管理员查看原文后决定是否启用。
- **已停用**：保留记录，但不再用于回复。

「召回记录」可以查看处理结果；「召回测试」可以输入一句话试试看。测试可能调用模型，但不会向群里发消息。

## 常见问题

**为什么刚说完的话没有变成记忆？**

插件不是逐句记笔记，而是分批整理。纯表情、单独链接等明显无信息的消息仍会保存为原文上下文，但不参与提取；其余消息默认每个群积累最多 80 条，或最早一条等待 15 分钟后再处理。只有被判断为值得记住、且有原文支持的内容才会留下，不是每句话都会成为记忆。

**能翻到安装前的聊天吗？**

不能。插件只记录启用后、允许记录的群里收到的新消息，不会自动拉取历史聊天。查看来源时，默认展开前后各最多 10 条已保存的消息；缺失的记录无法补回。

**会不会拖慢回复、增加费用？**

会。找到候选记忆后，需要额外调用模型判断和核验，主回复会多等一段时间。没有候选时，不会进行这些审核调用。后台整理和回复前核验都会调用辅助模型；插件不设置每日调用上限，Embedding 费用另计。管理页面会显示当天的辅助模型调用次数。

如果「召回记录」经常显示超时，可以检查模型速度，或适当调大「单次在线时间预算（秒）」。默认是 3 秒，最多可设为 30 秒；等待时间越长，对回复速度的影响也越明显。

如果调用失败，「召回记录」会显示失败阶段和可确认的原因（如上游 HTTP 状态、模型返回空内容或 JSON 格式错误）；后台提取失败可看管理页的「最近后台状态」。出于隐私与密钥安全，不会原样展示上游报错正文。

**原文片段太长，会不会挤爆聊天模型的上下文？**

插件会在回复前估算本轮消息和工具占用的 token，并给模型输出留余量。空间紧张时先减少来源附近的聊天；如果连必要的原文也放不下，就跳过本轮记忆注入，正常回复仍会继续。「召回记录」会说明原因。这个估算不是模型的精确 tokenizer，不能替其他插件或模型服务保证绝对不超限。

**模型一定能记对吗？**

不能保证。原文核验可以减少误记，但模型仍可能误解玩笑、语境或时间。重要信息请查看来源，不要把记忆当成已经确认的事实。

## 数据与隐私

- 启用前请确认有权记录这些群聊。记忆和原文保存在 AstrBot 主机上；提取和核验时，相关聊天内容会发送给你配置的模型服务。启用语义检索后，记忆摘要和查询文本也会发送给 Embedding 服务。
- 原文默认保留 30 天，但仍被记忆引用的来源会继续保留。可在设置中调整保留期限。
- 用于回复的记忆片段会随对话保存。删除插件中的记忆，**不会同时删除 AstrBot 会话历史、模型服务日志或备份中的副本**。
- 自动检索按群隔离；拥有管理权限的人可以在面板中管理各群的记忆。

聊天数据库未加密，请保护好主机和备份，也不要将管理页面直接暴露到不可信网络。
