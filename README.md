# Eyewitness Memory · 群聊记忆

让 AstrBot 记住群友聊过的事，回答前还能翻回原话核对。

比如，小林在群里说过：

> 我准备在十月参加学校的绘画比赛，现在还在画草稿。

过了一阵，有人问「小林之前说的比赛是什么时候？」，插件会查找相关记忆，连同当时前后的聊天交给辅助模型核对。核对通过后，主聊天模型才会拿到这份参考。

**群友照常聊天就行，不用发记忆命令，也不用让主模型主动调用记忆工具。**

支持 **OneBot/QQ 群聊（aiocqhttp）及 QQ 官方机器人群聊**，不支持私聊。它不会让机器人主动插话，只在 AstrBot 本来就要回复时查找记忆。官方机器人只能记录平台实际投递给它的消息；群映射不会扩大官方接口的收消息权限。

![记忆库：按群筛选，搜索并管理群友的偏好、计划、事件和约定](docs/images/memory-library.png)

*管理页面实拍。本文截图均使用虚构人物和演示数据，不含真实群聊。*

## 可以拿它做什么

- **记住聊过的事**：偏好、计划、事件和约定，例如「咖啡不加糖」「准备参加比赛」。
- **记不清时翻原话**：每条记忆都带来源，能查看是谁、什么时候说的，以及附近的聊天。
- **各群各记各的**：A 群的聊天不会被拿到 B 群回答；重置普通会话也不会清空记忆库。
- **在网页里管理**：查看、修改、停用、删除记忆，或者测试一句话能找到什么，不用记一堆命令。

## 怎么装

需要 **AstrBot 4.28.1 及以上的 4.x 版本、Python 3.11+**，并且已经接好 QQ 群聊和聊天模型。

### 1. 安装插件

在 AstrBot 的插件管理中，使用这个仓库地址安装：

```text
https://github.com/camera-2018/astrbot_plugin_eyewitness_memory
```

### 2. 填好三个设置

打开插件配置：

| 设置项 | 怎么填 |
| --- | --- |
| 辅助模型 | 从 AstrBot 已配置的聊天模型中选一个。用于整理记忆和核对原文，需要能按要求返回 JSON；可以与主聊天模型不同。 |
| 请求 JSON 对象输出 | 对已验证支持 `response_format=json_object` 的 OpenAI Chat Completion 渠道开启。记忆请求使用 JSON 模式和 `temperature=0`，不修改共享模型配置或主聊天请求。 |
| 允许记录的群 | 填完整会话标识，例如 `default:GroupMessage:123456`。`default` 要换成实际的平台标识，`123456` 换成群号，不能只填群号。 |
| 插件开关 | 改为「启用」并保存。 |

群里有其他机器人时，把它们的账号填入「其他机器人 ID」，避免把机器人说的话当成群友记忆。

新安装默认关闭，白名单也为空，**不会自动记录所有群**。建议先开一个熟悉的群，观察提取出来的内容是否合适。

### 同一个群换了平台接口

QQ 官方机器人提供的群 OpenID 与 OneBot 的数字群号不同，也不能直接换算。确认两边是同一个群后，在「同群跨平台映射」中填写一项：

```text
qq_official:GroupMessage:GROUP_OPENID=default:GroupMessage:123456
```

白名单只填右侧的统一群标识。之后这个官方群的新消息与旧 OneBot 群共用记忆，历史记忆无需搬迁。不同平台的原始消息和引用仍分别保留，不会因消息 ID 相同串引用，也不会修改 AstrBot 的发消息目标。映射不猜测群友身份：官方用户 OpenID 与数字 QQ 仍是不同标识，不能只凭昵称把两个人合并。已有其他群的数据不会因新增映射被自动搬入。

### 定时整理与遗忘

在设置中开启「定时整理记忆」后，默认每 24 小时扫描白名单群。首次启用从当前时间计时，重启不会重置下一次执行时间。过期、缺失或失效来源的记忆会停用；摘要完全相同且同群、同人、同类型、同立场的重复记忆保留一条（事件与约定还必须有共同原文，避免合并不同经历）；自述混入其他作者证据时退回待审核。不会依据关键词、相似度或“长期未被召回”删除记忆。

可另开「语义整理」，使用当前辅助模型检查临时接梗、被明确更正的旧说法等。默认任意连续 24 小时最多检查 32 条、最多 4 次模型请求；手动执行和重启也共用持久化限额，失败和中断仍占用次数，无自动重试。

将「每日语义复核上限」设为 `0` 可取消每日总条数和请求次数限制，用量仍会记录。不限模式每轮只处理启动时的待审记忆，每批最多 8 条串行执行；本轮新增或改版的记忆留到下轮。同一版本成功审查后 7 天内不重复检查。自动整理独立运行，不占住后台提取和索引循环，异常或超时会结束本轮。

每条决定必须有原文证据，涉及更正时还要有同人同群、时间更晚的对照。本人的明确陈述不会仅因模型认为“价值不高”就停用；这类建议转为待观察，仍可正常召回。含糊或缺证据时保留，独立的历史事件不会只因发生在过去就删除。模型仍可能误判，停用状态和版本记录可供检查与恢复。

整理采用可恢复的停用，不永久删除来源、不延长旧记忆有效期；原文、修改前版本和处理原因保留。设置页可先预览规则整理，再立即执行一次完整整理。立即执行包含已启用的语义整理，会产生辅助模型用量；平时的下一次计划时间会显示在页面中。

### 3. 打开管理页面

从 AstrBot 的「插件页面」进入「群聊记忆」。它沿用 AstrBot 登录，**不需要另开端口，也没有额外的登录 Token**。在这里修改设置，会同步到 AstrBot 原生插件配置。

插件从启用后开始积累新消息，不会补抓以前的聊天，所以刚装好时记忆库为空是正常的。

<details>
<summary>可选：让“换一种说法”也更容易找到记忆</summary>

只配置辅助模型就能使用，默认按关键词检索。

如果希望「喜欢拿铁」和「平时喝什么咖啡」这样的不同说法更容易关联，可以再配置：

1. AstrBot 中的 **Embedding 模型**：将文本转成用于比较相似度的向量。
2. **Qdrant 地址**：保存这些向量，提供相似内容检索。

两者都配置后才会启用语义检索。Qdrant 不替代本地记忆库，它保存的是可重建的索引；请勿复用其他插件的 Collection。需要鉴权时填写 Qdrant API Key，管理页面不会回显已有密钥，留空保存会保留原值。

「纯语义候选最低分」默认是 `0.55`。调低会让更多候选交给模型核验，也可能增加调用；它不是“记忆正确的概率”，不同 Embedding 模型的分数也不能直接比较。

</details>

<details>
<summary>可选：用 FastBrain / Jev / Clef 帮忙排序候选</summary>

如果网关支持 **System One 决策接口**，可以打开这一项。不需要另填密钥：在「System One 提供方」选择已配置的 AstrBot 提供方，插件只复用它的地址与密钥，不调用该提供方的聊天模型。

| 设置项 | 示例 |
| --- | --- |
| System One 模型名 | `FastBrain-9B`、`jev-1.13.0` 或 `clef-flash` |
| 接口路径 | FastBrain：`/fastbrain/v1/systemone`；New API Jev 插件：`/typesafe/v1/systemone`；Clef 插件：`/clef/v1/systemone`；直连服务：`/v1/systemone` |
| 排序时间上限 | 默认 3 秒，且不超过本轮剩余预算的四分之一 |

开启「System One 原文初核」时，它先看候选是否相关，再用该候选自己的局部聊天做原文初核，把更有希望的候选排在前面。**不会因它说“不相关”就删除候选，也不会因它说“支持”就直接注入**；原有辅助模型仍负责提取记忆和最终逐字核验。超时或报错不重试，保留候选继续核验。面板的召回记录与用量统计会显示这部分调用。

FastBrain 建议关闭「System One 原文初核」（`systemone_check_support=false`），只使用相关性概率排序：每个候选只调用一次，时间预算耗尽时也能保留已经完成的排序分数。它的原文支持判断尚不可靠，最终逐字证据核验始终保留。

这会增加决策模型调用，并不承诺减少原有辅助模型调用。留空提供方或模型名即可关闭。

</details>

## 记忆是怎么用上的

平时，插件会把白名单群的新消息分批整理成记忆。默认积累 **80 条待处理消息**，或最早一条等待 **15 分钟**后开始处理，不是每收到一句话就调用模型。只在本地去掉没有正文的消息组件、纯表情等内容，并对重复消息去重；一句话是否有记忆价值，由辅助模型结合前后聊天判断，不按固定词语筛掉。

等机器人准备回复时，再走下面这条路：

```mermaid
flowchart TD
    A[机器人准备回复] --> B[从本群记忆库查找候选]
    A --> Q[辅助模型理解问题并补充检索线索]
    Q --> B
    B --> S[辅助模型比较较宽的候选摘要池]
    S -->|选出值得核对的内容| C[辅助模型对照原文和前后聊天核验]
    C -->|相关且有依据| D[将记忆和原文片段追加为本轮参考]
    D --> E[主聊天模型回复]
    S -->|没有相关候选| E
    C -->|不相关、失败或超时| E
```

辅助模型先结合当前问题、会话和实际引用理解检索目标，最多补充 **3 条检索线索**。原问题始终独立检索，不会被模型改写替代；补充线索也不是事实或证据。理解失败时保留原问题继续查找，不按固定词语判断要不要召回。

默认让辅助模型比较最多 **24 条候选摘要**，选出最多 **6 条**值得查原文的内容，再分批并行核验，每批最多 3 条。不会在模型选择之前先截成 3 条；最终最多加入 **2 条记忆**，实际长度仍受上下文预算限制。候选池和原文核验数量都可以在原生配置或管理页面调整。

引用关系来自平台实际回复的消息；当前会话的近期正文也会作为一条独立检索线索，不拿群里其他人的插话冒充本轮话题。候选选择失败时保留有界候选继续核验；未完成原文核验的内容不会注入。

插件不靠闲聊、命令或回忆关键词表决定要不要召回。先按实际文本匹配、人物对应和向量相关性找候选，再让辅助模型读当前问题、会话与引用，决定候选能否提供有用背景。没有合适候选时不调用核验模型；有关联的候选仍可能在核验后被拒绝。这样不能保证每句闲聊都零调用，但不会仅因某种措辞就强行拦掉记忆。

辅助模型偶尔会在 JSON 里多写 `confidence` 等字段；只要协议字段有效，插件会忽略这些额外字段。过长的 `reason` 解释会截短，完整的 JSON 代码块可以解析；缺少必需字段、类型错误和截断的 JSON 仍会失败，不补造字段。

引用只在空白字符不同、且能唯一对应同一条原文中的连续片段时，恢复成原文后再校验、保存。不会做模糊匹配、改写文字或拼接多条消息，虚构来源仍会被拒绝。这些兼容处理不会重新请求模型，也不会自动重试旧的失败批次。

候选选择与核验先判断本轮的对象和具体需求，不用孤立称呼或泛词牵出私人往事；有明确语境的简短偏好咨询仍可召回。结构化输出有效不代表候选有用，最终仍需通过相关性与原文校验。

记忆只追加到本轮用户输入的末尾，不改系统提示词、不回改旧消息，并随会话保存。空间不够时会缩短周边聊天，必要原文也放不下就跳过记忆，让机器人照常回复。

这里的「召回」就是**从已有记忆里找相关内容**；「注入」就是**把核验通过的内容交给主聊天模型参考**。找到候选，不代表一定会用。

## 翻回原话，不只看一句摘要

在「记忆库」点开一条记忆，就能看到来源。直接支持这条记忆的发言会标出 **「直接来源」**，旁边还会展开已经保存的前后对话。

![来源详情：直接来源、附近聊天、发言人、用户 ID 和带时区的时间](docs/images/source-context.png)

每个来源默认向前、向后各取最多 **10 条**，重叠部分去重。每句话都会标明昵称、用户 ID 和时间；拿不到平台发送时间的旧记录，会明确写成「采集时间（发送时间未知）」。

这里只能展示**插件已经采集且仍保留的消息**，不是完整的 QQ 聊天记录。面板里能看到的片段也不一定会全部交给主模型，实际长度还受上下文预算限制。

## 页面里的几个状态是什么意思

| 状态 | 会不会用于回复 |
| --- | --- |
| 生效中 | 未过期时可以参与检索，但每次使用前仍要核验，不是直接当成事实。 |
| 待审核 | 不会使用。转述等不宜直接采信的内容可能进入这里，人工对照原文确认后可以改为生效。 |
| 已停用 | 不会使用，仍保留在管理页面中。 |

模型明确识别为玩笑、无法确认的陈述，或缺少有效来源的候选，不会保存成可用记忆。不过模型仍可能误判，重要信息请自行核对。

想看插件有没有起作用，可以打开：

- **召回记录**：默认看实际聊天的记录，也可切换手动测试；查看找到了什么、为什么使用或跳过，以及失败原因。
- **召回测试**：输入一句模拟提问，查看拟提供给主模型的内容。可能调用辅助模型，但不会向群里发消息。
- **记忆库首页**：查看实际聊天检查了几轮、注入了几次；手动测试另算，不混入注入率。也能查看最近 24 小时的辅助模型调用次数、失败次数和平均输入 tokens。
- **失败提取**：按批次查看失败原因和时间。确认模型服务恢复后，点「重新提取」手动入队，重复点击不会重复提交；再次失败仍不会自动重试。

## 常见问题

<details>
<summary>为什么群里聊了很多，还是没有记忆？</summary>

先检查插件是否启用、完整群标识是否填对、辅助模型是否可用，再看是否已经达到分批处理条件。它主要整理偏好、计划、事件和约定；纯闲聊、玩梗或没有可核对来源的内容不一定会留下记忆。

如果页面提示提取失败，可以直接看具体原因。空回答、超时或格式错误会记为失败，原文按保留周期保存，插件继续处理后续批次；**失败批次不会自动重试**，避免同一段聊天不断重复扣费。请求中途重启，也不会自动重发可能已扣费的请求。

对于 OpenAI 兼容提供方，本插件会关闭 AstrBot 与 SDK 的叠加重试：429 或连接失败只尝试一次，不轮换 Key 重试，也不修改主聊天和其他插件的重试设置。理解或选择阶段收到 HTTP 拒绝或空回答时，本轮直接报告失败，不再继续向同一提供方发起后续阶段请求。超时或无效 JSON 仍可保留原检索结果进入核验。它不会恢复已耗尽的上游额度，后续新批次仍按原计划处理。

</details>

<details>
<summary>明明有记忆，为什么这次没用？</summary>

有记忆不等于和当前问题有关。候选太弱、已过期、待审核、原文不足、核验失败、超时或本轮上下文空间不足，都可能跳过；具体看「召回记录」。

是否需要背景由辅助模型结合本轮话题判断，不使用操作词或闲聊词表。即使没有注入，也可能已经调用了问题理解或候选选择模型。检索和模型判断都可能漏掉隐含关联，不保证每次都能找全。

</details>

<details>
<summary>要多花多少模型费用？会不会拖慢回复？</summary>

新消息提取和回复前核验都可能调用辅助模型，没有每日调用次数上限；另行开启的定时语义整理有单轮记录数与请求次数上限。插件会先做本地筛选，并将候选合并核验；实际费用取决于群聊活跃度、模型价格和设置，Embedding 也可能单独计费。

在线检索与核验新安装默认最多等待 **30 秒**，旧安装保留自己的时间预算。问题理解、宽候选选择会增加模型调用和等待时间；这不等于一定找到更多正确记忆。排序出错会降级，原文核验出错或超时的内容不注入，不要求主模型等它成功。

页面中的 tokens 来自提供方返回的用量。没有返回的会标为「未知」，不会当成 0；统计只覆盖本插件的辅助模型调用，不包含主聊天、Embedding 或 SDK 内部重试，也不能补算旧版本数据。

调用登记或结束状态写入时遇到取消，插件会先完成结算再传递取消，避免留下永久 `running`。启动时仍会将上次异常退出遗留的调用标为「已中断、用量未知」，不会自动重发模型请求。

</details>

<details>
<summary>会把上下文撑满吗？reset 会丢记忆吗？</summary>

插件会估算本轮消息、媒体、工具定义、已有工具结果和输出预留占用，再决定能放下多少记忆。有图片或工具结果不会一律关闭记忆；放不下才缩短或跳过，不会无上限追加。估算时不读取媒体文件或下载 URL，但也不等于上游模型的精确计算，长音频、高分辨率图片、其他插件和上游差异仍可能导致超限。

记忆保存在 AstrBot 主机的独立 SQLite 数据库中，重启或 reset 普通会话不会清空它。已经加入会话的参考会随历史保存；正常的会话压缩和 reset 仍会改变历史，插件不承诺永久保持上游缓存。

如果装过旧名称的版本，请先备份并迁移数据，不要同时安装两份。

</details>

## 隐私与数据保留

请先确认有权记录这些群聊，并让群友知道：

- **保存在哪里**：原文和记忆保存在 AstrBot 主机，SQLite 数据库未加密，请保护好主机和备份。
- **会发给谁**：整理和核验时，相关聊天会发给辅助模型；开启语义检索后，相关文本还会发给 Embedding 服务。
- **留多久**：未被记忆引用的原文默认保留 30 天，被引用的来源会继续保留。这不是完整聊天归档工具。
- **删除到哪里为止**：删除插件中的记忆，不会自动清除已进入 AstrBot 会话历史的内容、模型服务日志或备份。

### FastBrain 召回前置判断（v0.1.28）

启用 `recall_gate_enabled` 后，先复用 System One 提供方和模型判断是否需要长期记忆。
只有 `unneeded` 概率达到 `recall_gate_skip_probability`（默认 0.90）才跳过本轮问题理解、候选选择和核验，直接继续主聊天。
`needed`、`uncertain`、低于阈值、接口未配置、非法响应和超时均继续原召回。模型概率不是经过校准的准确率。

历史追问、人物指代、引用消息和可能被截断的近期上下文保守放行，不依赖分类器拦截。
判断使用与原召回相同的最近最多六条纯文本上下文；不传图片或工具结果，也不复用主动插话提示词。
默认开关关闭，需先评估自己的语言和聊天样本再开启。`recall_gate_timeout` 默认 1.5 秒（含排队），同时最多占剩余在线预算的五分之一，失败不重试。

召回轨迹保存 `recall_gate` 的决策、概率、耗时和回退原因；模型调用统计单独记录「System One 召回需求」。
这里的跳过只影响当前轮记忆召回，不停用采集、后台提取、定时整理，也不直接授权任何记忆注入。
