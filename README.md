# Eyewitness Memory · 群聊记忆

让 AstrBot 记住群友聊过的事，需要时还能翻回原话核对。

比如有人说过“我报名了十一月的摄影比赛”。过了一阵他问“我的比赛是什么时候？”，机器人可以找到这段记忆、查看当时前后的聊天，再决定是否用它回答。群友不用发记忆命令，模型也不用主动调用记忆工具。

目前支持 **QQ 群聊（aiocqhttp）**，不支持私聊。插件只在 AstrBot 原本准备回复时查找记忆，不会让机器人主动插话。

## 快速开始

需要 AstrBot **4.28.1 及以上的 4.x 版本**和 Python **3.11+**。

1. 在 AstrBot 的插件管理中，使用仓库地址安装：`https://github.com/camera-2018/astrbot_plugin_eyewitness_memory`。
2. 打开「插件配置」，选择一个已配置的聊天模型作为「辅助模型」。它负责整理记忆、判断相关性和核对原文，可以与平时回复群聊的模型不同。
3. 在「允许记录的群」中填写完整会话标识，一行一个，例如 `default:GroupMessage:123456`。其中 `default` 要换成你实际使用的平台标识，不能只填群号。群里还有其他机器人时，把它们的账号填进「其他机器人 ID」。
4. 将「插件开关」设为「启用」并保存。新安装默认关闭、群白名单为空，因此不会自动记录所有群。

安装后可从 AstrBot 的「插件页面」打开「群聊记忆」。管理页面沿用 AstrBot 登录，不需要新端口或单独的 Token。插件配置页与管理页面的设置是同步的。

只配置辅助模型就能使用，默认按关键词找记忆。想让不同说法也能找到相近内容，再配置 **Embedding 模型和 Qdrant**；两者都配置后才会启用语义检索。Qdrant API Key 在管理页面不会回显，留空保存会保留原值。

如果装过旧名称的版本，请先备份并迁移数据，不要同时安装两份。

## 它怎么工作

- **先记录，再整理**：只保存启用后、白名单群的新消息，不能补抓安装前的聊天。明显无信息的消息仍可作为原文上下文保留，但不会送去提取记忆。默认每群积累最多 80 条待处理消息，或等最早一条满 15 分钟后整理；不是每句话都会变成记忆。
- **记忆带着出处**：插件保存相关原话。管理页面能查看来源前后各最多 10 条已保存的聊天，并标明发言人和时间；没有平台发送时间的记录会标成采集时间。转述、玩笑或主体不清楚的内容可能进入「待审核」，不会直接用于回复。
- **用之前再核对**：机器人要回复时，插件先找相关记忆，再让辅助模型核对原文。只有通过核验的内容才会作为用户级参考追加到本轮消息里，不改系统提示词或旧历史；这段参考会随会话保存。空间不足时先缩短周边聊天，必要原文也放不下就跳过本轮记忆，不影响正常回复。

各群记忆互相隔离；聊天会话 reset 不会清空插件的记忆库。

## 管理和排查

在「记忆库」可以查看、搜索、修改、停用或删除记忆。「生效中」表示可参与检索，但每次仍须核验；「待审核」和「已停用」都不会用于回复。

「召回记录」能看到本轮为什么用了或没用记忆，以及超时、模型输出异常等失败原因。「召回测试」可以试一句话会召回什么；测试可能调用辅助模型，但不会向群里发消息。后台提取状态也会显示在管理页面。

## 使用前要知道

- **会增加等待和模型费用**：后台整理、回复前判断与核验都可能调用辅助模型。插件没有每日调用上限；Embedding 也可能单独计费。在线核验默认最多等待 3 秒，可在设置中调整。
- **上下文预算是估算值**：插件会按本轮消息和工具占用估算 token，给模型输出留余量；它不是模型服务的精确 tokenizer，不能保证其他插件或上游绝对不会超限。
- **记忆不保证正确**：模型仍可能误解玩笑、时间或人物。重要信息请在管理页面核对原文。
- **群聊内容会被保存并发送给模型**：原文和记忆存于 AstrBot 主机；整理和核验会把相关聊天发送给辅助模型，启用语义检索后还会向 Embedding 服务发送文本。请先确认有权记录这些群聊。
- **删除范围有限**：未被记忆引用的原文默认保留 30 天；被引用的来源会继续保留。删除记忆不会自动清除已写入的 AstrBot 会话历史、模型服务日志或备份。聊天数据库未加密，请保护好主机和备份。
